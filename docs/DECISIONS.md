# Sea design decisions

A record of why Sea is built the way it is. Entries up to SEA-D15 are reconstructed (16 October 2026) from the code
comments, the README, `engine-notes.md` and the version notes; their "introduced" versions are approximate. Entries
from SEA-D16 record decisions made on that date or later. Suite-level direction lives in
[overview/DECISIONS.md](../../overview/DECISIONS.md); this file covers this mod only.

Status values: **Active** (implemented and current), **Superseded**, **Proposal** (not implemented, needs agreement).

## Active

| ID | Introduced | Decision | Why | Consequences and alternatives considered |
|---|---|---|---|---|
| SEA-D01 | 0.2 | The wind is a **pure function** of (wind key, world shape, config, position, game time). Only the inputs are sent: one packet on join, a fixed wind when an admin sets one | Every side computes the same wind without streaming weather. Vanilla already syncs the game time | Anything feeding the model must be pure and thread-safe on every side. Clients take the server's config. A client's calendar can be slightly behind the server's, so agreement is to within that. (0.4.0) The wind itself is now a provider's (SEA-D30), which must follow the same rule; Sea's own inputs (key, shape, config, fixed wind) still do |
| SEA-D05 | 0.2 | **Latitude comes from the game calendar** (`OnGetLatitude`), read live. Cylinder World's ring is read **by reflection** at `RunGame` | One source of latitude for every map: vanilla's realistic climate, Cylinder World, Earth, or a terrain mod's own. No build dependency on Cylinder World | Without realistic climate it's 45°N everywhere. (0.4.0) Latitude is only shown by `/sea` now (the belts and storms went to Earth, SEA-D30); the ring still matters for the waves |
| SEA-D06 | 0.3 | The waves are a **fixed library of wave trains** (12 swell wavelengths × 18 directions + 2 chop) made from the wind key. The sea state only sets their **amplitudes**; no train ever changes its phase | Ships need the surface on the CPU, the same on the server and every client, with nothing jumping when the weather changes. A per-frame noise or an FFT ocean can't be sampled cheaply and identically on every side | At most 24 trains are drawn at once (uniform budget, SEA-D11). On a Cylinder World ring every train fits a whole number of waves around it |
| SEA-D07 | 0.3 | The **wave clock is the server's running time** (`ElapsedMilliseconds`), sent every 5 s plus half the ping. Clients slew at most 2 %, and snap only when more than 1 s off | The calendar jumps on every server update and runs fast while players sleep | Waves never jump on a client. A paused singleplayer game stops the clock, as the server's does |
| SEA-D08 | 0.1 | **Sea owns the water shaders.** Its code is added as each shader loads, using text anchors. Ship mods register clip sources instead of patching the shaders. If a driver won't compile it, Sea steps down: everything → no dry cut → vanilla | One mod editing the water shaders avoids conflicting patches between ship mods. A driver that refuses the code never leaves the sea undrawn | A shader mod that rewrites the same lines makes Sea fall back (a log warning, and `.sea` shows it). `tests/ShaderCheck` must run after shader changes (the offline tests only see the text) |
| SEA-D09 | 0.3 | The **sheltered-water factor** (lakes get a fifth) is read from the region's `OceanMap` exactly as the chunk tesselator packs it into the water vertices | The server's ship motion then matches the waves drawn there | It follows whatever the world's `OceanMap` says, not the actual coastline (see [compatibility.md](compatibility.md)) |
| SEA-D10 | 0.3.0 | **Dry hulls are cut per pixel** in the water fragment shaders, and dryness for the camera, breathing, splashes and particles is answered by the ship mod (`IDrySpaces`) | A ship is an entity, not blocks, so the world's water can't be removed from inside a moving hull | Each underwater effect needs its own patch (camera, breathing, splashes, particles). Particles aren't cut by the shader, hence `DryParticles` |
| SEA-D11 | 0.3.0 | **Uniform budget:** 8 clips, 4 detailed dry outlines (4 × 32 half-widths), 24 wave trains | Fits OpenGL 3.3's guaranteed 256 vec4 of fragment uniforms, next to vanilla's own | More hulls nearby fall back to the footprint outline, or get no clip at all |
| SEA-D12 | 0.3.5 | A water particle is **judged over its whole life** (`IsDryWithin`), not just where it spawns | Specks stand still in the world's water while the hull sails through them | Ship mods answer for the next few seconds of hull motion. The default interface method is `IsDry` now |
| SEA-D13 | 0.2 | An admin's **fixed wind is saved with the world** and broadcast in the parameters packet | It must survive a restart and reach clients that join later | `/sea clearwind` returns to the weather |
| SEA-D14 | 0.1 | **Every Harmony patch goes in its own `Try`**: one that fails only switches off its own feature, and `.sea` lists what's active | Game updates break single patches, not the whole mod | Features can be silently partial. Check `.sea` and the log after a game update |
| SEA-D15 | 0.3 | **Sea state follows the past 16 game hours of wind** at the same place: a fast build-up and a slower swell decay. Waves run the way the wind has been blowing | Learnable seas: a storm's sea builds up and outlasts it | `SeaAt` costs 16 wind evaluations without gusts (~30–60 µs). The sea doesn't know coasts yet (SEA-P01) |
| SEA-D16 | 16 Oct 2026 (0.3.6) | **Both ends of each second's amplitude blend are worked out from fixed moments**, the game hours of samples n − 1 and n, at the place's current position. Nothing of a place's sampling history is used | Before, a place that had been sampled for a while, a new one, and one that missed seconds drew different surfaces at the same place and time. That broke the "same sea for everyone" contract (Codex review, 16 Oct) | `SeaAt` and `WindAt` are now worked out twice per place and second (~0.1 ms). What remains between sides is the server's ship and a client's copy of it being a few blocks apart. Not adopted: snapping positions to a grid. The fields vary over ≥ 300 blocks, so a grid would add steps without making ships agree better. The old one-end `WavePlace.Update` now holds the new sample after a gap instead of blending from a stale one |
| SEA-D17 | 16 Oct 2026 (0.3.6) | **The dry cut uses the hull's exact frame**, rebuilt from its waterline slopes: pitch = atan(`SlopeAlong`), tan(roll) = −`SlopeAcross`·cos(pitch), roll about the keel applied before pitch, measured from the waterline point above (X, Z). No new API fields | The small-angle shear used before left strips of water inside a hull that was pitched and rolled together. At 12° pitch and 20° roll it was off by about 0.3 blocks at the bow and the sides. The keel staying in the vertical plane of the heading fixes the frame uniquely from the two slopes, matching Hansa's `ShipFrame` | Exact for a hull whose origin is on its waterline. One whose origin is h below it is off by about h·tan(tilt) (Hansa: h = 0.1). The C# twin (`WaterClipBox.HullFrame`) and the GPU check agree pixel for pixel. Possibly related to the stern dry-outline failure in the ship test history; not verified |
| SEA-D20 | 16 Oct 2026 (0.3.6) | **A sample's game hour comes from the server's anchors** (`SampleHours`). Every 5 s the server says: from sample n + 3 on, hours run from the calendar's present reading at its present speed. It also checks once a second, and makes a new anchor at once when the calendar has left the newest one's line by more than 3 game minutes (`/time set`, sleep starting or ending). Each clock packet carries every anchor the server keeps, numbered in the order made; each side drops one once a later one covers every sample from two back on (so a burst of corrections can't drop one still needed), and ignores one it already had or dropped. Each side uses, for each sample, the latest anchor in force there. Until a client hears of one, it makes its own from its calendar | The calendar can't give a sample's hour. The server's moves in 200 ms steps (`ServerSystemCalendar`), each client's is a little off, and sleeping runs it ~20× faster. So "now worked back to the sample's start" differed between callers in the same second, and between sides (Codex second pass). A client joining on an anchor's first sample needs the one before it for its first blend (Codex third pass) | Every caller on every side gets the same hours for both ends of a sample's blend, once the client has the anchors (checked offline with a stepped, sleeping, jumping calendar and late clients). The sample hours lag a sudden calendar change by up to ~5 s of it. When sleep starts that's about 20 game minutes, which only affects the gusts. A client that hears of an anchor after it's in force (more than ~3 s of lag) differs until it does. The clock packet's anchors are a new optional field |
| SEA-D21 | 16 Oct 2026 (0.3.6) | **The wind key is random**, made once per world and kept in the save (`sea-windkey`) | The old seed-derived key gave the seed away to every client (SEA-D02) | Existing worlds get a new key once with 0.3.6: their winds, storms and wave phases change once. A world that crashes before its first save after that makes another key on the next start. Two worlds with the same seed no longer share their wind |
| SEA-D22 | 17 Oct 2026 (0.3.7) | **Over the 24-train budget, the trains kept are each less the strongest one left out** (`WavePlace`), ties broken by train number | Cutting the weakest off made a train vanish at full strength when the order changed while the sea turned: the surface jumped about 0.06 blocks (Codex seventh pass). Less the 25th, a train joins or leaves at nothing, so the surface stays continuous | Only while the sea turns (more than 24 trains in the blend): the swell is then a little lower than its sea state says, by at most the 25th train's height. Every side cuts alike. Not adopted: rescaling the rest to keep the energy (it can blow up when many trains are about equal) |
| SEA-D23 | 17 Oct 2026 (0.3.7) | **Dry places exist only in the world itself (dimension 0)**. `IDrySpaces` stays dimension-free; Sea doesn't ask it for creatures, cameras or particles in another dimension | Ships sail in dimension 0, and the providers (Hansa, Magelan) compare world positions only, so a creature at the same coordinates in a mini-dimension could breathe "in a hull" (Codex seventh pass) | No API change. A future ship mod with hulls in another dimension would need a dimension in the interface |
| SEA-D24 | 17 Oct 2026 (0.3.7) | **Numbers from outside are checked where they come in**: the config on load (negative, NaN or infinite → default), a fixed wind from the command, the save and the packet (any non-finite number → no fixed wind; strength clamped) | A NaN fixed wind reached every client's wave directions and train indices and was saved with the world; a negative storm speed made storms run outside the range searched for them (Codex seventh pass, own review) | A bad hand-edited value is replaced silently (the file is written back with the default). `WaveScale` now scales the chop too, so 0 flattens the sea; a ready but empty sea is sent to the shader as one train of nothing, since a count of 0 means vanilla's waves there |
| SEA-D25 | 17 Oct 2026 (0.3.7) | **Every numeric config member is always serialized** (`IsRequired`), so a 0 reaches clients | protobuf-net leaves out a field equal to 0, and the client's object starts from the constructor's defaults (1): a server with no storms, no gusts or `WaveScale` 0 had clients computing storms, gusts and waves it didn't (Codex eighth pass; present since the config was first sent) | Checked by a round trip through the game's serializer. The wire format only gains the zero fields; any new member with a nonzero default needs the same |
| SEA-D30 | 21 Oct 2026 (0.4.0) | **The wind comes from a provider; weather moved to Earth.** `SeaSystem.SetWindProvider(string name, Func<double, double, double, bool, ValueTuple<double, double>> windAt, Func<double, double, double, ValueTuple<double, double>> prevailingAt)` and `ClearWindProvider(string name)`, BCL types only, on every side, any time; one provider at a time (another name is refused until the holder clears it); `WindProviderName` says who. Order: an admin's fixed wind, else the provider's, else vanilla's wind for `WindAt` (ships) while the sea follows the config's steady wind (`SeaWindFrom` 270°, `SeaWindStrength` 0.3). Removed: Sea's belts, seasonal shift, drift, storms (`StormField`), gusts, `/sea storms`, config members 1–8 (numbers retired, never reused), `IPrevailingWinds`/`SetPrevailingWinds`, and every patch on vanilla's weather (`OnGetWindSpeed` handlers, `WeatherSimulationRegion.GetWindSpeed` postfix, `asyncParticleSpawn` rain-direction transpiler, the `particlesquad` rain-streak edit, the `CloudTick` drift prefix) | User direction, 21 Oct 2026: Earth owns climate and weather (prevailing winds by month, storms, rain, clouds) as a pure function of (world seed, x, z, game hours), the same on every side; Sea is the wave and water mod and only consumes the wind, through a generic call any mod can make. Earth drives rain amount and clouds too, and two mods must not patch the same vanilla weather code. The rain-streak edit existed only to slant rain with Sea's directional wind, so it went with the rain transpiler | Without Earth the world has vanilla weather (the user accepts that); the sea is still the same on every side. Ships and Wmap get the provider's wind unchanged: `WindAt`, `WindModel.At`/`SeaWind`/`Prevailing` route to it; Wmap's reflection binding still finds `Prevailing`, `At(x, z, h, bool)`, `BeltName` (now always null), `Mode` (`Off`/`Provider`) and `Shape`. The provider must be set on every side with the same pure, thread-safe functions, answer for past hours (the sea state looks 16 game hours back, gusts = false) and be fast (`SeaAt` asks it 16 times, twice per place and second). A non-finite or throwing answer counts as calm (counted, shown by `.sea`), a stronger one than 1.5 is capped. `/sea setwind` now fixes only Sea's sea and ships; vanilla's effects follow the provider. Not adopted: keeping Sea's weather as a fallback without Earth (two weather models to keep in step), and sending the wind (the provider is deterministic) |
| SEA-D31 | 21 Oct 2026 (0.4.2) | **Wave places sample the sea state on a 64-block grid.** `WavePlace.Sample` takes the sea state and wind at the four corners of the cell a place is in (both ends of the second, at the anchored sample hours) and blends the trains' amplitudes between them by position; `SeaSystem.SampleWaves` uses it. On a ring the cell is the nearest spacing that fits the circumference a whole number of times. A second's start is reused from the last second's end when the cell, the anchored hour and `IWaveSource.Revision` (bumped by a provider, a fixed wind or a new model) are unchanged | Claude + Codex review: the blend's ends were sampled wherever a place first asked in that second, so two ships at the same spot and time could differ by where they came from (with a provider's wind varying in space); the server probe re-sampled up to 64 blocks away | The surface is a function of (x, z, wave time) alone and changes smoothly as a ship crosses cells (offline checks). A place resamples at once, even mid-second, when `Revision` changes (the model's changes plus the anchors' `Version`); writers bump it before and after a change and a sample re-checks it when done, so one worked out across a change on another thread is redone at that place's next call. `SeaAt` reads the fixed winds and provider once for all 16 hours. On a client `WaveHeightAt` stays the drawn surface (the camera's trains, as the shader draws all water), so away from the camera it can differ slightly from the server's; ship physics runs on the server. Cost per place and second: 4 corners × one end, against 1 place × two ends before. The old `Update` overloads stay for mods that drive a `WavePlace` themselves. Not adopted: re-sampling at every position change (a jump mid-second) |
| SEA-D32 | 21 Oct 2026 (0.4.2) | **An admin's setwind/clearwind takes over at a wave sample a moment ahead and leaves the old sea dying down.** `ChangeOverride` (used by `/sea setwind` and `/sea clearwind`) stamps the new fixed wind with `ActiveSample` (three wave samples ahead) and ends the old one there (`Ended`, `EndSample`, `EndHours` = that sample's anchored hour), keeping it in `WindModel.History` (oldest first, dropped 17 game hours after it ended by the hour of the oldest sample still blended, not the calendar, which a `/time set` moves ahead of the samples for a few seconds; at most 64, beyond which the oldest go with a warning). A fixed wind is judged per wave sample (`AppliesAt(hours, sample)`): before its sample the old state reads exactly as before, after it an ended one still decides the hours before its end. Hour-only questions (`WindAt`, `SeaAt(x, z, hours)`) are answered as known now. Both are sent (`SeaParamsPacket` member 8, an array) and saved (`sea-override-history`); from a save, samples restart (in force from the first, ended ones ended). `SetOverride` keeps its 0.4.1 meaning (at once, history cleared), which Magelan's self-tests rely on | Review (Claude, then Codex on the fix): a fixed wind reached clients a ping after the server used it; clearing one rewrote 16 hours of history so its swell vanished at once; a calendar-hour gate did nothing with the calendar stopped, and keeping only one ended wind lost a storm replaced and cleared within the hour (or one scheduled twice before taking over) | Every side changes at the same sample, whatever the calendar does. With the calendar stopped no time passes for the sea to calm, so a cleared storm's past hours stay stormy until it moves. Old saves and old servers' packets read as before |
| SEA-D33 | 21 Oct 2026 (0.4.2) | **Leaving a world switches Sea's shader code off; the next world finds out afresh.** On client dispose Sea zeros `seaWaveCount`, `seaClipCount`, `seaEffects` and Wmap's `seaNightFloor` in the programs the game keeps, and `Hooks.Remove` resets the "injected" flags | The game loads shaders once per process (`ScreenManager.DoGameInitStage2`) and reloads them without Sea's patch from the main menu's graphics settings; Sea's code and last uniforms stayed live in a world without Sea, and a stale flag skipped the reload in the next world with it | A world joined after another reloads the shaders once at `LevelFinalize`. Not adopted: reloading every shader on world exit (slow, and the exit path has no world) |
| SEA-D34 | 21 Oct 2026 (0.4.2) | **Sea's water numbers are worked out in the Before stage (0.99) and go in on the game's own `Use` of a water program** (a `ShaderProgramBase.Use` postfix, once per program and frame); the old explicit `Use`/`Stop` stays as a fallback when the patch fails, and either path logs once and stops instead of throwing inside the frame | Review: an extra full activation per program per frame, `Use` throws when another program is current, and (Codex on the fix) the game's liquid depth pass (Before 0.995) got the last frame's numbers while the drawn water got this frame's | After the ships' pose update (Magelan, Before 0.1), so clips aren't a frame behind | Hull clips are validated before upload (length, inset, finite numbers) and the shader mirrors the CPU's zero-length guards |
| SEA-D38 | 24 Oct 2026 (review round 1, not released) | **Sea's Harmony patches are two sets, each counted under one lock.** The patches both sides need (breathing, splashes: id `sea`) are counted across sides; the client's (water shader, compile fallback, water uniforms on `Use`, eyes in water, the particle transpilers: id `sea.client`) are applied and removed only by the client's `SeaSystem`, on its main thread. A dedicated server applies the client's set too, so the self-test still checks them | Review S1-1 (Claude + Codex): in singleplayer the integrated server is disposed after the client, on its own thread, and its last `Remove` unpatched everything while the main menu drew through the patched `ShaderProgramBase.Use`; and the unsynchronised count let a world starting during that unload lose its patches | The server thread no longer touches render-path detours or the shader flags. Not verified in game (a singleplayer exit and rejoin). Not adopted: unpatching on a main-thread task (the client is gone by then) |
| SEA-D40 | 25 Oct 2026 (0.4.7-pre.5) | **One colour for the sun, its glitter path and the sunset sky.** While AstraTerra draws the sun (`SunDiscRenderer.HidesVanillaSun`) the glint takes its `Twilight.SunColour`; otherwise the game's reflect colour reddened by Sea's copy of that table (pre.4). The sky reflection, here and (through `seaSunset`) on Wmap's far sea, draws AstraTerra's sunset glow (`SunsetScatter.Shown`, the same shape) | Play-test issue 5: an orange glitter path under a pale sun. pre.4 capped the colour by the game's reflect colour, which on some days is redder than the disc; the pale disc was AstraTerra's (dev.20 fixes it) | AstraTerra's sun pieces are bound apart from the moon adapter: an older AstraTerra (dev.18) leaves them to Sea's table and the moon adapter works (SkyIntegrationCheck against both). Not seen in game |
| SEA-D41 | 25 Oct 2026 (0.4.7-pre.5) | **Near water and far sea fade the waves by one rule and reflect one sky.** Each train fades once shorter than about four pixels (Wmap's `wmapWaveNormal`: 1 − smoothstep(0.25, 0.75, k × blocks per pixel)); near water estimates blocks per pixel at its vertices from the distance, the grazing angle and `seaPixel` (2 / (projection[1][1] × frame height)), and keeps the faded slope as roughness that widens the glint lobe (energy kept). Wmap divides the far slopes by `seaWaveFactor` (the shader's oceanity divisor at the camera) instead of 5. `seaSkyColor` has the game's flat fog and its horizon raised by the eye's height (`seaAboveSea`) | The screenshot's band: aliased full-contrast crests to the near water's edge against a smooth far sea, far slopes a fifth of the open sea's, and a near reflected sky without the flat fog the far sea's `getSkyColorAt` has | GPU: water variants and Wmap 0.5.0-pre.6's far programs compile with the new uniforms live; the glow and flat-fog reflection check. The footprint estimate is analytic against Wmap's `fwidth`; continuity across the seam not seen in game |
| SEA-D39 | 24 Oct 2026 (review round 1, not released) | **The 64-block grid's corners are worked out once for every place in a cell** (`SharedCorners` in front of the wave source): a corner's sea state and wind are kept by (position, game hour, sample, the inputs' revision) for the last few samples, behind a lock | Review S1-2: the camera and every ship in a cell (and the server's ships and wave probes) each asked the provider 4 corners × 17 times a second for the same numbers | Every place gets identical numbers, so the sides still agree (offline checks). The anchors' version isn't in the key (the hour is), so a new anchor no longer asks the provider again. Nothing is kept before the model exists (vanilla's wind isn't a pure function). Not measured in game |

## Superseded

| ID | Introduced | Decision | Why | What replaced it |
|---|---|---|---|---|
| SEA-D02 | 0.2; superseded by SEA-D21 | The wind key is **derived from the seed**, not the seed itself | Clients must not learn the world seed from Sea's packet | **Superseded:** the mix used (SplitMix64's finalizer) is invertible, so the seed could be recovered from the key (Codex fourth pass) |
| SEA-D03 | 0.2; superseded by SEA-D30 | Vanilla's wind lookups keep **the strength in X**. The direction exists only in Sea's API, and the effects that need it are patched one by one (rain, clouds, rain streaks) | Every vanilla consumer reads X as "the strength" (shader uniforms, sound, boats, fruit trees, body temperature) | **Superseded by SEA-D30 (0.4.0):** Sea no longer feeds vanilla's wind lookups or patches its rain and clouds; Earth drives vanilla's weather |
| SEA-D04 | 0.2; superseded by SEA-D30 | Sea's `OnGetWindSpeed` handler is subscribed in `StartServerSide` / `StartClientSide`, after vanilla's (subscribed in `Start`), so **Sea has the last word** | No patch on vanilla's weather code is needed for the wind value itself | **Superseded by SEA-D30 (0.4.0):** Sea has no `OnGetWindSpeed` handler or region-wind postfix any more; Earth has them |
| SEA-D18 | 16 Oct 2026 (0.3.6); superseded by SEA-D30 | **The drawn water always shows Sea's waves, the ones ships sample.** With `WindModel` `Off` they follow Sea's *steady* winds (prevailing and gusts, `WindModel.SeaWind`), and vanilla's wind drives everything else | Before, `Off` drew vanilla's random bumps while ship mods kept riding Sea's trains, so ships pitched against water that wasn't there. Vanilla's wind can't drive them either: it changes from tick to tick and reaches each client at another moment (Codex third pass) | **Superseded by SEA-D30 (0.4.0):** `WindModel` `Off` is gone. Without a provider the drawn sea and ships still share Sea's waves, following the config's steady wind (`SeaWindFrom`, `SeaWindStrength`) instead of Sea's steady belts |
| SEA-D19 | 16 Oct 2026 (0.3.6); superseded by SEA-D30 | **Once a second the latitudes are fingerprinted** (nine places down the map), and when they change the storms worked out so far are forgotten. The storm cache is kept in **generations**: forgetting starts a new one | On a client, Sea's model can be built before the game's latitudes arrive. Storms cached at 45°N then stayed wrong for the rest of that game day (~48 real minutes). Vanilla swaps the data behind a latitude function it installed earlier, so the function itself can't show the change. A lookup still running on another thread (weather particles) could put stale storms back into a cleared cache (Codex second pass) | **Superseded by SEA-D30 (0.4.0):** Sea has no storms or belts, so nothing of its own depends on latitudes; a provider using them handles a late arrival itself |
| SEA-P02 | Proposal; superseded 21 Oct 2026 by SEA-D30 | Rain amount following Sea's storms | README "Not yet". Vanilla's precipitation comes from its own region patterns | **Superseded by Earth (SEA-D30):** Sea has no storms any more; Earth owns weather, rain amount and clouds with its own storms |

## Proposals (not agreed)

| ID | Proposal | Details |
|---|---|---|
| SEA-P01 | Coast-aware waves: smaller in sheltered water near land, not only by the ocean map's oceanity | README "Not yet". Must stay the same on the server and the client, so it needs a deterministic shelter field both can compute |
| SEA-P03 | Run-time check with Terra Prety + Watersheds (and other generators) | [compatibility.md](compatibility.md), "What to verify" |
| SEA-P04 | Optional `WaterClipBox` field for the waterline's height above the hull's origin, making SEA-D17 exact for any origin | Only if a ship mod's origin is far from its waterline |
| SEA-P05 | Coexistence with other water-shader mods: more tolerant anchors, or an explicit include file they can keep | Only once a concrete mod is reported to conflict |
| SEA-P06 | **Wmap's far water by contract, with Sea's waves** (23 October 2026, pre-release 0.4.7-pre.1 on branch `wmap-far-waves`, for Wmap 0.5.0-pre.2): Wmap declares `seaNightFloor`, `seaSkyReflect`, `seaWaveCount` and `seaWave` in its far programs and does the shading; Sea sets them when the game uses those programs (its Use hook, as for its own water) and adds its wave trains, so the distant sea's normals follow the near water's waves. Sea's text patch of `farterrain` stays for Wmap 0.4.x and skips a shader that declares the uniforms | Wmap 0.5's mid-distance view drew the far sea up to 768 blocks with a second program (terraces) that Sea's patch, keyed on the pass name `farterrain`, never reached: a teal ring where Sea's near water ended (reported in game at Santorini). A contract Wmap owns keeps working as Wmap's shaders change. Checked: `tests/ShaderCheck` and `tests/SkyIntegrationCheck` against Wmap 0.4.11 and the 0.5 branch (`WMAP_ROOT`), `tests/SeaTests`; Wmap's smoke check calls Sea 0.4.6's patch on its shader. Not checked in game: the waves on the far sea and the join |
